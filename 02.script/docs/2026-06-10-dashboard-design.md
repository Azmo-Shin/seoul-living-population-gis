# 설계: 서울 생활인구 GIS 시각화 대시보드

- 날짜: 2026-06-10
- 목적: `shin_project.생활인구_250m`(2.26억 행) 위에 **구→동→격자 드릴다운 지도 + 일/주/월 시간집계** 대시보드.

## 1. 화면 요구 (요약)
**공간 드릴다운**
- 서울 전체 → **구별** 비교 (성/연령 분포 지도)
- 특정 구 → **동별** 비교 (+ 성/연령 선택 시 격자 히트맵)
- 특정 동 → **격자별** 비교

**시간 모드**
- 일간: 특정일의 **시간대(0~23) 변동**
- 주간/월간: 주중/주말 구분(**공휴일·대체공휴일→주말**), **시간대 선택 합산**, 합계 + 일평균
  - 시간대는 사용자가 선택(예: 새벽 제외). → 마트에 `시간`을 차원으로 유지.
  - 일평균 = 합계 ÷ 일수(주중일수 / 주말+공휴일 일수).

## 2. 아키텍처 (계층)
```
팩트   생활인구_250m (2.26억, 월파티션+압축) — 직접조회 X
차원   ├─ 달력  : 일자→요일·주중주말·공휴일(holidays)            [02.build_calendar.py]
       └─ 공간  : 구/동/격자 GeoJSON(WGS84) + 격자→동→구 매핑    [03.build_spatial.py]
마트   마트_월_시간 : (연월,행정동코드,250M격자,주중주말,시간)→SUM(생활인구합계+28)  [04.build_mart.py]
        · 연월 파티션. 구별=LEFT(동코드,5) · 동별=동코드 · 격자별=격자 롤업.
        · 주간/일간은 원천 직접조회(일자 인덱스) + 달력 조인.
API    FastAPI: routes_meta(구/동 목록) · routes_map(GeoJSON) · routes_query(집계)
프론트  React+Vite + deck.gl(격자 1만 폴리곤 GPU렌더) + react-map-gl + zustand + Plotly
```

## 3. 조인 키 (검증됨)
- 행정동: shp `ADSTRD_CD` == `행정동코드` (커버 99.3%, 누락 3개 그레이스풀)
- 격자: shp `CELL_ID` == `250M격자` (커버 100%, 누락 2개)
- 구: 행정동코드 앞 5자리 = 구 (시군구 shp 코드체계 다름 → 동 dissolve 또는 이름매핑)
- 좌표: shp 5186/5181/5179 → **WGS84(4326) 변환** (샘플 lat37.46/lon126.99 정상)

## 4. 성능 근거
- 원천 직접조회 = 10~60초(불가) → 마트로 226M→~1,400만 행.
- 조회는 한 달 슬라이스(~48만 행)만: 구별 0.1~0.4s · 동별 <0.1s · 격자 0.2~0.5s.
- 마트 `연월` 파티션 → 선택 달만 스캔. 시간대 선택 = `시간 IN(...)` 합산.
- 지도: deck.gl GPU로 격자 1만 폴리곤 60fps.

## 5. 스택 (2026_05_text 패턴 준수)
- 백엔드 FastAPI(API 전용 포트) + 프론트 React+Vite(별도 포트) + CORS.
- 라우트 도메인별 분리. config.py 상수관리. `backend/`·`frontend-react/` 분리.
- 지도: deck.gl + react-map-gl, 베이스맵 VWorld/Kakao/MapLibre.

## 6. 빌드 순서
① 달력 차원 → ② 공간 차원(GeoJSON) → ③ 마트 → ④ 백엔드 API → ⑤ 프론트. (데이터 레이어 ①~③ 먼저)

## 7. 메트릭 정의 (확정)
- 생활인구 집계 = **합(SUM)**, 시간대 사용자 선택.
- 일평균 = 합계 ÷ 일수. 주말일수 = 토·일 + 공휴일·대체공휴일, 주중일수 = 나머지.
